fall-graft · mutation-gated

Fourteen live apps drew their whole interface and ran no JavaScript.

They had been cut in half by the thing that was supposed to add a feature to them.

An injector appended its block at a byte offset. On fourteen pages that offset landed inside the host <script>, in the middle of a statement:

function report(x) {
  return `<!doctype html><html><body>
    <p>${x}</p>
<!-- AUTOPILOT -->                       ← the block, written here
<script type="module"> … </script>      ← and the page ends, right here
  </body></html>`;              ← the host script's own next line
}

A browser ends a <script> at the first </script> it meets — inside a string, inside a template literal, it makes no difference. So the host script stopped there and everything after it stopped being code: 622 lines in one app. Every page still drew, because the static HTML around it was untouched. That is why nobody noticed.

fallaccount-trades shipped with 44 controls, 25 click handlers, and zero functions defined. It looked completely normal.

The rules it follows

Never write inside a script. The insertion point is chosen from the document's structure, never from a byte count. An offset knows nothing about what it is landing in the middle of.

Never write a block twice. One app carried two, so repairing one left it just as dead.

Never write a page that does not parse. The result is compiled before it is returned. A graft that would break the page is refused, with the reason, instead of written.

Using it

node inject.mjs check  page.html          # is a block sitting inside a script?
node inject.mjs add    block.html page.html   # graft it safely, or refuse
node inject.mjs repair page.html          # move a block that is already inside one
